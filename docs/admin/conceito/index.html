Admin: conceito visual

Tese visual: o admin vira uma bancada escura em três camadas de cinza medidas da referência (fundo #0e0e0e, cartões #181818, selecionado #222222), com a cor só para estado e uma única ação branca por tela. O editor de case usa a tela inteira, com a prévia do site sempre ao lado, e o movimento se limita a 120–200 ms de opacidade e 4 px de deslocamento.

Padrões permitidos: ponto de estado ao lado de "Salvo" (reporta o estado real), divisória de 1 px entre linhas de lista (a lista é uma tabela), mono só em endereços e variáveis, separador "·" em metadados (empresa · ano).

O DNA completo está em docs/admin/conceito/admin-design-dna.json. As capturas do "antes" vêm da auditoria de 12/11. No "depois", textos, títulos e imagens são os reais do admin; só os estados (hover, "Salvo há 3 s") são exemplos.

Pergunta: esta direção vale para o admin todo? Se sim, aplico primeiro o menu e a lista de cases, depois o editor.

Entrei no PicPay com mais um designer. Antes de contratar, desenhamos a solução completa para o lojista e organizamos o time a partir dela.

  • A prévia ocupa 44% e fica aberta a partir de 1200px; abaixo disso vira uma aba. Hoje ela só abre sozinha a partir de 1400px.
